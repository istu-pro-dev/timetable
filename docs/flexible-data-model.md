# Данные без жёсткого формата: проект

Дата: 2026-10-20

## Коротко

Идея верная: ядру нужны не данные конкретного вуза, а их **форма** — граф из занятий, аудитории, преподавателей, помещений и слотов времени. Но «любой JSON» сам по себе проблему не снимает. Трудность не в синтаксисе (xls, JSON, CSV), а в смысле:

- что считается одной сущностью: «Соболева Н.В.» и «Соболева Наталья Владимировна»;
- как закодированы чётность недели и подгруппы («над чертой», позиция в ячейке);
- что значит пустое поле: «нет данных», «не нужно» или «ошибка»;
- какие ресурсы эксклюзивные: аудитория — да, спорткомплекс — нет.

Поэтому предлагаем три слоя: канонический граф (`ttx`) → декларативный маппинг вместо кода адаптеров → сопоставление сущностей. Ядро (engine) видит только граф и проверяет правила над **типами связей**, а не над «преподавателем» или «аудиторией».

## 1. Канонический граф (уже есть: `ttx/1`)

Узлы: `group`, `teacher`, `room`, `place`, `period`, `lesson`. Рёбра: `lesson → audience (group[/subgroup])`, `lesson → teachers`, `lesson → room|place`, `lesson → slot`.

- Это контракт. Любой источник, который отдаёт `ttx`, загружается без кода: `POST /api/review` уже принимает JSON Lines.
- Неизвестные `kind` пропускаются, недостающие справочники достраиваются из занятий. Можно прислать одни `lesson` — и это уже работает.
- Отсутствующие поля (`capacity: null`, `size: null`) — не ошибка. Проверка, которой нужно поле, выключается и пишет «нет данных». Так уже сделано для H6 и «пустых мест».

## 2. Маппинг как данные, а не код

Сейчас адаптер — это Go-код (`internal/ingest/tandem`). Для табличных и JSON-источников код можно заменить файлом маппинга:

```yaml
# mapping/vuz-x.yaml
source: { type: json, items: "$.schedule[*]" }   # или csv: { delimiter: ";" }
lesson:
  day:        { from: "$.weekday", map: { "1": mon, "2": tue, "3": wed, "4": thu, "5": fri, "6": sat } }
  period:     { from: "$.pair" }
  parity:     { from: "$.week", map: { "числ": odd, "знам": even, "": every } }
  discipline: { from: "$.subject.name" }
  teachers:   { from: "$.teachers[*].fio", normalize: fio_short }
  audience:   { from: "$.groups[*]", group: "$.code", subgroup: "$.sub" }
  room:       { from: "$.room", regex: '(?P<code>\d+-\w+)' }
```

- Движок маппинга — около 300 строк на Go: JSONPath/колонка → поле, словари значений, регулярки, несколько стандартных нормализаторов (ФИО, шифр группы, время → номер пары).
- Черновик маппинга по образцу файла можно генерировать (эвристики или LLM). Человек подтверждает его на превью: «вот 20 разобранных занятий, верно?».
- Код-адаптеры остаются только для раскладок, где смысл задаётся геометрией листа (Тандем: подгруппа = позиция в объединённой ячейке). Таблицей это не описать.

## 3. Сопоставление сущностей

Это главная ручная работа в любой интеграции, и формат её не убирает.

- Таблицы алиасов `*_aliases(entity, alias, source)`: повторный импорт проходит без ручной работы.
- Отчёт «не сопоставлено» с кандидатами: та же фамилия и инициалы, пересечение дисциплин.
- Ключи из источника хранятся рядом с нашими: потом можно сверять версии файла (diff между выгрузками).

## 4. Ядро над типами ресурсов

Сейчас правила H1–H3 — три разных кода для преподавателя, группы и аудитории. Обобщение:

- у ресурса есть тип и флаг `exclusive`;
- H1–H3 превращаются в одно правило «эксклюзивный ресурс занят дважды»;
- аудитория в группе — иерархия (группа ⊃ подгруппы деления), это уже есть в `domain.Audience`;
- у занятия может быть несколько ресурсов одного типа (несколько преподавателей). Сейчас engine допускает одного.

Тогда новый вуз с другими ресурсами (лаборант, оборудование, онлайн-лицензия) подключается без изменений engine. В `review` это уже сделано вручную: спорткомплекс — неэксклюзивный ресурс (у каждого занятия своя копия), занятие с несколькими преподавателями — «составной» преподаватель. Это временные обходы до обобщения engine.

## 5. Порядок работ

1. ✅ `ttx/1` как вход системы, парсер Тандема T1 и проверка `POST /api/review` + страница `/review`.
2. Engine: `Teachers []int32` вместо одного преподавателя и флаг `exclusive` у ресурсов. Убирает оба обхода из `review`.
3. Адаптеры T2–T5 (заочка по датам, «по дням»): на файлах с сайта они сейчас отвечают «поддерживается только недельная раскладка».
4. Декларативный маппинг для JSON/CSV и превью с подтверждением.
5. Алиасы, отчёт «не сопоставлено», хранение версий файлов (`sources`, `observed_lessons`) — `docs/istu-data-format.md` §5.
